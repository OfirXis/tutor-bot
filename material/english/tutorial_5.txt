# Tutorial 5 — Dynamic Programming (Continued)

## Source and Scope
These English notes summarize the supplied Hebrew slides `material/lectures/Tutorial algo 5.pdf` (75 PDF pages), titled "Dynamic Programming — Continued; Design and Analysis of Algorithms, Tutorial Five" (תכנון דינאמי-המשך — תכנון וניתוח אלגוריתמים, תרגול חמישי). Page references below refer to PDF pages (1–75). Repeated animation slides are consolidated. The deck continues dynamic programming with five exercises: minimum vertex cover on trees (a two-value recurrence per vertex, a correctness proof and a worked table), the longest path in a directed acyclic graph (DAG) whose vertices are numbered so that every edge goes from a smaller to a larger number, edit (Levenshtein) distance between two strings, counting the tilings of a $2 \times n$ room with L and I tiles, and the diameter of a tree. The slides say that DAGs have further special properties that will be studied later in the course; they do not present a topological-sort algorithm, and they do not cover coin change or matrix-chain multiplication.

## Core Concepts
### Vertex Cover and Minimum Vertex Cover — PDF pages 2–5
Vertex cover (כיסוי בצמתים) is defined for an undirected graph $G = (V, E)$: a vertex cover of $G$ is a set of vertices $\tilde{V} \subseteq V$ such that for every edge $(v, u) \in E$, either $v \in \tilde{V}$ or $u \in \tilde{V}$ (or both). A minimum vertex cover (כיסוי מינימלי בצמתים) of $G$ is a minimum set of vertices that is a cover of $G$. The slides note that on a general graph this is an NP-complete problem, that is, a hard one, which students will study in depth in the Computational Models course (מודלים חישוביים). The exercise of this deck restricts the input to trees, as the opening section title announces: "Minimum Vertex Cover on Trees (Using Dynamic Programming)" (כיסוי מינימלי בצמתים על עצים, בעזרת תכנון דינאמי). The problem slide appears three times with no extractable differences between the builds (see PDF pages 3–5; diagram not fully extractable).

### Directed Acyclic Graph (DAG) — PDF pages 33–35
A directed acyclic graph (גרף מכוון חסר מעגלים), abbreviated DAG in English and גמ"ל in Hebrew, is described in the slides as a graph that contains only simple paths; in particular, it contains no cycles. The slides add that graphs with this property have several special properties, but that these will be studied later in the course. A small example graph on vertices A–E is drawn (see PDF page 33; diagram not fully extractable). The exercise that follows uses a directed graph $G = (V, E)$ whose vertices are named $V = \{1, 2, \ldots, n\}$ and whose edges all have the form $(i, j) \in E$ with $i < j$; in words, every edge enters a vertex whose number is larger than that of the vertex it leaves. The slides state that in particular such a $G$ is a DAG and leave the reason as a question ("why?"). The solution then remarks that this edge property gives a certain order on the vertices (PDF page 36). The deck does not call this a topological order and gives no algorithm for ordering the vertices of a general DAG.

### Edit Distance — PDF pages 40–41
Edit distance (מרחק עריכה), given the English title "Edit (Levenshtein) distance" on the slides, is defined for two strings $a, b$ with $|a| = n$ and $|b| = m$. The edit distance between $a$ and $b$, denoted $\mathrm{dist}(a, b)$, is the minimum number of operations needed to turn one string into the other, where the allowed operations are: insert one character into the string, remove one character from the string, and change one character in the string. The definition slide illustrates this with MOVIE → MOVE → LOVE: delete the character I, then replace the character M by L, and conclude $\mathrm{dist}(\text{MOVIE}, \text{LOVE}) = 2$. In the solution slides the strings are called $X$ and $Y$, the distance is written $d(X, Y)$, and operations are written $x \to y$ (change $x$ into $y$), $-x$ (delete $x$) and $+x$ (insert $x$).

### Tree Diameter — PDF pages 63–65
Tree diameter (קוטר בעץ), introduced under the section title "longest path (diameter) in a tree" (מסלול ארוך ביותר (קוטר) בעץ), is defined for a given tree $T = (V, E)$. A diameter of the tree is a path between two vertices of the tree such that no other path in the tree is longer than it. In particular, the slides state, a diameter of a tree must be a path between two leaves of the tree. The word is used in two senses: sometimes "diameter" refers to the path itself and sometimes only to its length. The solution (PDF pages 66–75) is built around the LCA (lowest common ancestor) of a path with respect to an arbitrary root, together with the depths of subtrees; the slides use the abbreviation LCA without defining it.

## Algorithms and Complexity
### Minimum Vertex Cover on Trees by Dynamic Programming — PDF pages 6–11
Minimum vertex cover on trees (כיסוי מינימלי בצמתים על עצים) is solved by rooting the tree arbitrarily, so that subproblems can be defined on subtrees and the solution assembled from their solutions. The observations on the way to the solution (הבחנות בדרך לפתרון) are: every vertex is either in the cover or not; if it is not, all of its children must be in the cover so that the edges to them are covered; if it is, those edges are covered and the children need not be in the cover, although a child may still be in the cover when that is what makes the cover minimal.

The vertices are visited by levels, from the lowest level up to the root $r$, and $c(i)$ denotes the set of children of $i$ after rooting; the slides say that later in the course students will learn to do this simply and in linear time. Each vertex $i$ stores ${+}_i$, the minimum number of vertices of the subtree of $i$ in the cover when $i$ itself is in the cover, and ${-}_i$, the same minimum when $i$ does not have to be in the cover. Then ${+}_i = 1 + \sum_{j \in c(i)} {-}_j$ and ${-}_i = \min\{{+}_i, \sum_{j \in c(i)} {+}_j\}$. The size of the minimum cover is ${-}_r$; how to recover the cover vertices themselves is left as a question. Correctness can be proved by induction, similarly to the algorithm itself (see Theorems and Proofs). Apart from the remark on rooting, no running time is stated.

### Longest Path in a DAG — PDF pages 36–39
Longest path in a DAG (מסלול ארוך ביותר בגרף מכוון וחסר מעגלים) is solved for the numbered graph in which every edge $(i, j)$ satisfies $i < j$; the slides note that this fact gives a certain order on the vertices. For each vertex the algorithm keeps $\mathrm{OPT}(i)$, the length of the longest path that starts at $i$ and ends at $n$. The slides claim $\mathrm{OPT}(i) = \max_{(i, j) \in E} \{\mathrm{OPT}(j) + 1\}$, so every edge adds 1 to the length, and leave the proof to the students ("prove this claim!"). The vertices are processed from the end to the beginning, and the $\mathrm{OPT}$ value of each vertex is computed and stored. All $\mathrm{OPT}$ values needed for vertex $i$ are already computed at that point, because they belong to vertices with larger numbers than $i$. The algorithm returns $\mathrm{OPT}(1)$; how to upgrade it to find the vertices of the path is left as a question. Each vertex is passed over exactly once, and the slides give the running time $O(|V| + |E|)$. The extracted slides do not state a base case for $\mathrm{OPT}(n)$ or say how vertices from which $n$ cannot be reached are treated.

### Edit Distance Recurrence — PDF pages 45–49
Edit distance (מרחק עריכה) is computed by looking at the first characters of $X$ and $Y$, denoted $x$ and $y$, and assuming by induction that the minimum sequence of operations for equalizing any two suffixes (סיפות) of $X$ and $Y$ is known. If $x = y$, the optimal solution may simply be the solution for the suffixes $X[1:]$ and $Y[1:]$. In any case there are further options, each paying one operation: change $x \to y$ and use the optimal solution for $X[1:], Y[1:]$; delete $x$ and use the optimal solution for $X[1:], Y$; or insert $y$ and use the optimal solution for $X, Y[1:]$. The edge cases are $|X| = 0$ or $|Y| = 0$, where all remaining characters are handled with $|Y|$ or $|X|$ operations respectively. The resulting recurrence is $d(X, Y) = |X|$ if $|Y| = 0$; $d(X, Y) = |Y|$ if $|X| = 0$; $d(X, Y) = d(X[1:], Y[1:])$ if $X[0] = Y[0]$; and otherwise $d(X, Y) = 1 + \min\{d(X[1:], Y),\ d(X, Y[1:]),\ d(X[1:], Y[1:])\}$. The first two cases are the base cases, the third is the case $x = y$, and the last takes the minimum over all the possible operations. Here $X[0]$ is the first character of $X$ and $X[1:]$ the suffix that remains after removing it.

### Edit Distance Table and Running Time — PDF page 50
Edit distance (מרחק עריכה) is evaluated with a table. The slides note that the recursive formula $d(X, Y)$ depends only on the same formula applied to suffixes of $X$ and $Y$. Therefore a table of size $|X| \times |Y|$ can be built and its cells computed starting from the small suffixes, until $X$ and $Y$ themselves are reached at the end. Computing each cell costs $O(1)$, because all the earlier computations it needs already appear in the table. Hence the complexity of the whole algorithm is $O(|X| \cdot |Y|)$. In the example run on PDF pages 51–52, the table has one row per non-empty suffix of the first string and one column per non-empty suffix of the second, plus a row and a column for the empty suffix that hold the base cases, and the answer appears in the cell of the two full strings.

### Tiling Recurrences — PDF pages 57–62
The tiling recurrences (נוסחאות נסיגה) for the tiling problem (בעיית ריצוף האריחים) use two quantities: $A_i$, the number of different ways to tile a floor of size $2 \times i$, and $B_i$, the number of different ways to tile a $2 \times i$ floor without one of its corners. The solution to the problem is $A_n$; example floors labelled $A_4$ and $B_7$ are drawn (see PDF page 57; diagram not fully extractable). A $2 \times i$ floor can be tiled using only four recurrence rules, giving $A_i = A_{i-1} + 2 \cdot B_{i-1} + A_{i-2}$ for $i \ge 2$. There is one way to tile a $2 \times 1$ floor and one way to tile a $2 \times 0$ floor (not tiling at all), so $A_i = 1$ for $i \in \{0, 1\}$; a floor with negative $i$ clearly cannot be tiled, so $A_i = 0$ for $i < 0$. The recurrence for $B_i$ is even simpler and has only two rules: $B_i = A_{i-2} + B_{i-1}$ for $i > 2$. $B_2$ is exactly an L-shaped floor of size 3, so there is only one way to tile it, $B_2 = 1$; for $i < 2$ the floor has size less than 3 and cannot be tiled at all, so $B_i = 0$. Since $A_i$ and $B_i$ depend only on $A_j, B_j$ with $j < i$, both are computed in increasing order while the previous values are kept, and the answer is $A_n$. The time complexity is linear, because constant work is done for each element.

### Tree Diameter by Subtree Depths — PDF pages 73–75
Tree diameter (קוטר בעץ) is computed by rooting the tree arbitrarily at $r$ and visiting the vertices from the deepest ones first up to the root last. At each vertex $v$ with children $c(v)$, two values are computed. The depth of the subtree of $v$, measured in edges, is $d(v) = 1 + \max_{u \in c(v)} d(u)$. The length of the longest path whose LCA is $v$ is $\pi(v) = 2 + \max_{u \in c(v)} d(u) + \max^{(2)}_{u \in c(v)} d(u)$. On the slide the second maximum carries a mark that the extraction does not preserve; since the path passes through two different subtrees of $v$, it is read here as the second-largest child depth (see PDF page 74; formula not fully extractable). The answer is $\max\{d(r), \max_{v \in V} \pi(v)\}$, as observed earlier: either the best path that passes through two subtrees of some vertex, or the downward path from the root measured by the depth of the tree. The slides state that the running time is linear, since a constant number of operations is performed at each vertex. The extracted slides do not spell out $d$ for leaves or $\pi$ for vertices with fewer than two children.

## Worked Examples
### Example: Minimum Vertex Cover of a 14-Vertex Tree — PDF pages 15–31
Minimum vertex cover on trees (כיסוי מינימלי בצמתים על עצים) is posed as an exercise: describe an algorithm, with as good a complexity as possible, that finds the minimum vertex cover of a given tree, and prove its correctness and complexity (PDF pages 3–5). The example solution (פתרון דוגמה) applies ${+}_i = 1 + \sum_{j \in c(i)} {-}_j$ and ${-}_i = \min\{{+}_i, \sum_{j \in c(i)} {+}_j\}$ to a tree with 14 vertices labelled A–N; the shape of the tree is not recoverable from the extracted text (see PDF pages 15–31; diagram not fully extractable). Starting from an empty table, one row is filled per frame, in the order A, B, …, N, with the pairs $({+}, {-})$: A, B, C, D, F, G and J each get $(1, 0)$, the base-case values of a leaf; E and H get $(1, 1)$; I and K get $(2, 2)$; L gets $(3, 3)$; M gets $(3, 2)$; and N gets $(6, 6)$. M is the only non-leaf row in which ${-}$ is strictly smaller than ${+}$. Reading N, the last row filled, as the root $r$, the minimum vertex cover of the example tree has ${-}_N = 6$ vertices. The final two frames repeat the complete table with no new extractable values (see PDF pages 30–31; diagram not fully extractable).

### Example: Longest Path from Vertex 1 to Vertex n — PDF pages 34–39
Longest path in a DAG (בעיית המסלול הארוך ביותר בגמ"ל) is posed for a directed graph $G = (V, E)$ with $V = \{1, 2, \ldots, n\}$ in which all edges have the form $(i, j) \in E$ with $i < j$, so every edge enters a vertex with a larger number than the vertex it leaves; in particular $G$ is a DAG, and the slides ask why. Students must describe an algorithm, with as good a complexity as possible, that finds the length of the longest path that starts at vertex 1 and ends at vertex $n$, and prove its correctness and complexity. A graph on vertices 1–5 illustrates the setting (see PDF page 34; diagram not fully extractable). The presented solution defines $\mathrm{OPT}(i)$ as the length of the longest path that starts at $i$ and ends at $n$, uses $\mathrm{OPT}(i) = \max_{(i, j) \in E} \{\mathrm{OPT}(j) + 1\}$, evaluates the vertices from the last to the first so that every needed value is ready, and returns $\mathrm{OPT}(1)$ in $O(|V| + |E|)$ time. Two tasks are left to the students: proving the recurrence, and extending the algorithm to output the vertices on the path.

### Example: Edit Distance Between Two Strings — PDF pages 41–50
Edit distance (מרחק עריכה) is posed as an exercise: given two strings $a, b$ with $|a| = n$ and $|b| = m$, describe an algorithm, with as good a complexity as possible, that finds the edit distance between them, the minimum number of single-character insertions, removals and changes that turn one string into the other, and prove its correctness and complexity. The definition slide's example is $\mathrm{dist}(\text{MOVIE}, \text{LOVE}) = 2$: delete I, then change M into L. The presented solution first shows that an optimal sequence never changes a character twice, never changes a character and then deletes it, and never inserts a character and then changes it, and that the order of the operations does not matter. It then compares the first characters of the two strings. If they are equal, it uses the solution for both suffixes; otherwise it pays one operation for a change, a deletion or an insertion and recurses on the matching pair of suffixes, $d(X, Y) = 1 + \min\{d(X[1:], Y),\ d(X, Y[1:]),\ d(X[1:], Y[1:])\}$. When one string is empty, the cost is the length of the other. Filling a table over all pairs of suffixes takes $O(|X| \cdot |Y|)$ time.

### Example: Edit-Distance Table for MOVIE and LOVE — PDF pages 51–52
Edit distance (מרחק עריכה) is traced in an example run (דוגמת הרצה) on MOVIE and LOVE, the pair from the definition slide. Each row stands for a suffix of MOVIE starting at M, O, V, I or E, with a last row for the empty suffix; each column stands for a suffix of LOVE starting at L, O, V or E, with a last column for the empty suffix. The first frame shows only the base cases: the empty-suffix column holds 5, 4, 3, 2, 1 for rows M to E, and the empty-suffix row holds 4, 3, 2, 1, 0. The completed table, with columns L, O, V, E and empty, reads: row M 2, 2, 3, 4, 5; row O 2, 1, 2, 3, 4; row V 3, 2, 1, 2, 3; row I 3, 2, 2, 1, 2; row E 3, 2, 1, 0, 1. The top-left cell gives $d(\text{MOVIE}, \text{LOVE}) = 2$, in agreement with the definition slide. One extracted cell, row I and column V, that is $d(\text{IE}, \text{VE})$, reads 2, although the recurrence applied to its neighboring cells gives $1 + \min\{1, 1, 0\} = 1$ (change I into V); this does not affect the final answer (see PDF page 52; possible slide or extraction error).

### Example: Tiling a 2×n Room with L and I Tiles — PDF pages 53–62
The tiling problem (בעיית ריצוף האריחים) gives a room of size $2 \times n$ that must be tiled completely. There are two kinds of tiles, L tiles and I tiles (אריחי L ואריחי I), and the tiles may be rotated and flipped in any direction. Two tilings are considered different if at least one tile is placed differently in them. Given $n$, the question is how many different ways there are to tile the room. The tile shapes appear only in a picture (see PDF page 54; diagram not fully extractable); the base cases are consistent with an I tile covering a $2 \times 1$ floor and an L tile exactly filling the 3-cell L-shaped floor $B_2$. The solution counts full floors $A_i$ and floors missing one corner $B_i$, with $A_i = A_{i-1} + 2 \cdot B_{i-1} + A_{i-2}$, $B_i = A_{i-2} + B_{i-1}$ and the stated base cases, and returns $A_n$ in linear time. Judging from the formulas, the four rules for $A_i$ end the floor with one I tile ($A_{i-1}$), with two I tiles ($A_{i-2}$), or with an L tile in one of two mirror-image placements that leaves a floor missing a corner ($2 \cdot B_{i-1}$); a floor missing a corner is completed by an L tile ($A_{i-2}$) or by an I tile ($B_{i-1}$) (see PDF pages 58–61; diagram not fully extractable).

### Example: Diameter of a Tree — PDF pages 64–75
Tree diameter (קוטר בעץ) is posed as an exercise: given a tree $T = (V, E)$, describe an algorithm, with as good a complexity as possible, that finds its diameter, and prove its correctness and complexity. The solution roots the tree at an arbitrary vertex $r$, looks at another arbitrary vertex $x$, names the two ends of a diameter $a$ and $b$, and asks where the diameter can pass at all; the drawings place $r$, $x$, $a$ and $b$ in several relative positions (see PDF pages 66–70; diagram not fully extractable). The conclusion is that (almost) every path has an LCA with respect to $r$, at which it passes through two different subtrees, and that the only other candidate is a downward path from the root to the deepest leaf, measured by the depth of the tree. The algorithm therefore computes, from the deepest vertices up to the root, the subtree depths $d(v) = 1 + \max_{u \in c(v)} d(u)$ and the longest path $\pi(v)$ whose LCA is $v$, which adds 2 to the two largest child depths, and returns $\max\{d(r), \max_{v \in V} \pi(v)\}$. The slides state that this takes linear time.

## Theorems and Proofs
### Correctness of the Tree Vertex-Cover Recurrences — PDF pages 12–14
Minimum vertex cover on trees (כיסוי מינימלי בצמתים על עצים) is proved correct (הוכחת נכונות) in two parts. First, the cover is valid, that is, every edge is covered. Every edge connects a parent $i$ to its child $j$. If the parent is taken as ${+}_i$, it is part of the cover and the edge is covered. If the parent is taken as ${-}_i$, then according to the algorithm its child is taken through ${+}_j$, so the edge is covered by the child.

Second, the cover is optimal, by induction. Base case: for a leaf $\ell$, ${+}_\ell = 1$ and ${-}_\ell = 0$; the subtree of a leaf has no edges, so a valid minimum cover has size 0, and the minimum cover required to contain $\ell$ is the leaf alone, of size 1. Induction step: assume ${+}_j, {-}_j$ are optimal for all direct children $j$ of $i$. When $i$ is required in the cover, the edges to its children are covered, so each child subtree may take its smallest cover; the subtree covers are independent of one another, so the result is optimal and matches the formula for ${+}_i$. When $i$ is not required, leaving $i$ out forces all of its children into the cover, so, again by independence, each subtree takes its optimal cover containing its own root, which is optimal when $i$ is not in the cover. Taking the minimum of the two options gives ${-}_i$ and an optimal cover.

### Structure of an Optimal Edit Sequence — PDF pages 42–44
Edit distance (מרחק עריכה) is analyzed through observations about an optimal sequence of changes from a string $X$ to a string $Y$, each proved by contradiction with the sequence being the shortest. First, no character is changed more than once: if the same letter is changed $x \to y$ and later $y \to z$, both operations can be deleted and replaced by the single change $x \to z$, which gives a solution with one fewer operation. Second, no character is changed and then deleted: if $x \to y$ is followed by the deletion $-y$, both can be replaced by $-x$, again saving one operation. Third, no character is inserted and then changed: if $+x$ is followed by $x \to y$, both can be replaced by $+y$. Finally, every operation is local and affects at most one character, so the order of the operations does not matter. After these observations the solution examines only the first characters of the two strings (PDF pages 45–49).

### Candidate Paths for the Tree Diameter — PDF pages 66–72
Tree diameter (קוטר בעץ) is approached through observations (הבחנות בדרך לפתרון) that start by rooting the tree at an arbitrary vertex $r$, looking at another arbitrary vertex $x$, and naming the two ends of the diameter $a$ and $b$; the question is where the diameter can pass at all (see PDF pages 66–70; diagram not fully extractable). (Almost) every path between two vertices of the tree has an LCA with respect to $r$. If for every vertex one can compute the maximum length of a path that passes through two different subtrees of that vertex, the maximum over all these paths is the diameter. The paths that have no LCA, in the slides' usage, are only the downward paths. If such a path is a diameter, one of its ends is the root: otherwise its upper end would be another vertex with the path descending from it, and the path could always be extended by adding vertices up to the root. Since a diameter must be a path between two leaves, the deep end of such a path is the deepest leaf of the tree. Therefore another candidate for the diameter is the depth of the tree, and this path is indeed a diameter only if the root is itself a leaf.
