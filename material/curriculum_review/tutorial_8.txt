# Tutorial 8 — Shortest Paths

## Source and Scope
These English notes summarize the supplied Hebrew slides `material/lectures/Tutorial algo 8.pdf` (51 PDF pages), titled "Shortest Paths" (מסלולים קצרים ביותר), with the subtitle "Semester A 5784 — challenge tutorial" (סמסטר א תשפ"ד – תרגול אתגר). Page references below refer to PDF pages (1–51). Repeated animation slides are consolidated. The deck is a sequence of exercises that model a problem as a graph, often transform the graph, and then apply a known shortest-path algorithm as a black box: lightest paths that must use a given edge, lightest paths with integer weights from 1 to 10, Boolean matrix multiplication through an all-pairs shortest paths (APSP) algorithm, a lightest path with a half-price coupon, a shortest path whose edge colors alternate, a lightest path whose edges may not exceed a weight limit $L$, and the smallest such limit. Bellman-Ford and Dijkstra's algorithm are invoked with their stated running times, BFS is used whenever every edge can count as 1, and Floyd-Warshall is only named. The slides do not present the steps or correctness proofs of these algorithms, do not mention relaxation or negative cycles, and do not explain why Dijkstra's algorithm is avoided when weights can be negative.

## Core Concepts
### Lightest Paths in Weighted Graphs — PDF pages 1–51
Lightest paths (מסלולים קלים ביותר) are the subject of every exercise in this deck, whose title is "Shortest Paths" (מסלולים קצרים ביותר). The exercises work in weighted graphs, several of them directed graphs $G=(V,E)$ (PDF pages 3, 37 and 49), and the lightest path from $u$ to $v$ is the path of minimum total weight, cost or price. The slides use "lightest" (הכי קל) and "shortest" (הכי קצר) interchangeably for this, for example on PDF pages 6 and 32. Each exercise fixes its own assumptions on the weights, and the chosen tool follows them. Weights that can be negative lead to Bellman-Ford, chosen explicitly "because the weights can be negative" (PDF page 5). Positive weights (PDF page 32) and nonnegative road prices (PDF page 44) lead to Dijkstra's algorithm. Integer weights from 1 to 10 could also be handled by Dijkstra, but the deck reaches linear time with BFS (PDF pages 13–17). When all weights are 1, or the graph has no weights at all, BFS suffices (PDF pages 13 and 23). For all pairs of vertices with general weights, the deck assumes an APSP algorithm such as Floyd-Warshall (PDF page 19).

### Reversing the Graph for Paths Into a Vertex — PDF pages 6–8 and 34–35
Reversing the graph (להפוך את הגרף) is how the deck obtains lightest paths from every vertex to one fixed vertex. The question is posed on PDF page 6: how do we find the shortest path from every vertex to $a$? The answer on PDF page 7: instead of running Floyd-Warshall (פלויד ורשאל) and looking at the lightest path to $a$, reverse the graph and run Bellman-Ford from $a$. The lightest path from $a$ to $u$ obtained this way has to be reversed to serve as the $u \to a$ part of the answer, and the whole solution keeps the running time of Bellman-Ford, $O(VE)$ (PDF page 8). The same idea returns in the coupon exercise: run Dijkstra's algorithm from the source $u$, then reverse the graph and run Dijkstra from the destination $v$, which gives the costs from $u$ to every vertex and from every vertex to $v$ (PDF page 34).

### All-Pairs Shortest Paths (APSP) — PDF pages 18–29
All-pairs shortest paths (מסלולים קצרים ביותר בין כל הזוגות), written in the slides in English as "APSP (All pairs shortest path)", asks for shortest paths between every pair of vertices. The deck assumes some APSP algorithm for general weights, for example the Floyd-Warshall algorithm (אלגוריתם פלויד-ורשאל), and uses it as a black box (קופסא שחורה); its steps and running time are not given (PDF pages 19 and 21). When the graph has no weights, the slides note that even BFS from every vertex works (PDF page 23). The deck's point is a reduction: Boolean matrix multiplication can be solved in quadratic time plus one APSP computation. Consequently, if APSP were improved to $o(n^3)$ time, even only for weights $1$ and $\infty$, Boolean matrix multiplication would be improved as well without any further work (PDF page 29). Floyd-Warshall is also mentioned on PDF page 7, as the all-pairs alternative that reversing the graph avoids.

### Boolean Matrix Multiplication — PDF pages 19–20
Boolean matrix multiplication, called multiplication of binary matrices (כפל מטריצות בינאריות) in the slides, is the problem the deck solves with an APSP algorithm. The ordinary product of two matrices $A, B$ is defined by $C_{ij} = \sum_{r=1}^{n} A_{ir}B_{rj}$. In the binary product the sum is replaced by OR and the multiplication by AND, so $C_{ij} = \bigvee_{r=1}^{n} (A_{ir} \wedge B_{rj})$ (see PDF page 20; formula not fully extractable). Hence $C_{ij} = 1$ exactly when some index $r$ has $A_{ir} = B_{rj} = 1$; the correctness proof on PDF pages 26–27 uses the definition in this form. The slides remark that the naive algorithm for multiplying binary matrices is also the best algorithm known to date, up to improvements in the constants.

## Algorithms and Complexity
### Bellman-Ford Algorithm (Used as a Black Box) — PDF pages 5–8 and 40–42
The Bellman-Ford algorithm (בלמן-פורד) is used in two exercises of this deck. In the first, it is run from $b$ to find the lightest path from $b$ to every other vertex, "because the weights can be negative" (PDF page 5), and again from $a$ on the reversed graph to get the lightest paths from every vertex to $a$ (PDF page 7). Its running time is given as $O(VE)$, and the whole solution of that exercise has the same complexity (PDF page 8). In the alternating-color exercise, which asks for $O(VE)$ time (PDF page 37), Bellman-Ford is run from both $s$ and $s'$ in the duplicated graph, and the time complexity is stated to be that of Bellman-Ford (PDF pages 40–41). The deck treats Bellman-Ford as a black box: it does not list its steps or prove its correctness, does not discuss relaxation or negative cycles, and, beyond the remark on PDF page 5, does not explain why Dijkstra's algorithm is not used when weights can be negative.

### Dijkstra's Algorithm (Used as a Black Box) — PDF pages 13, 34–35 and 47–48
Dijkstra's algorithm (דייקסטרא, as the slides spell it) is used in the exercises whose weights are positive or nonnegative, with the running time $O(E + V\log V)$ stated on PDF pages 35 and 48. For road costs that are integers from 1 to 10, the slides say one can clearly just run Dijkstra, and then look for a better, linear-time solution (PDF page 13). In the coupon exercise, which has positive weights, Dijkstra is run twice — from the source $u$, and from the destination $v$ on the reversed graph — for a total of $O(E + V\log V)$ (PDF pages 32–35). In the edge-weight limit exercise, which has nonnegative prices, it is run once on the graph left after deleting the edges heavier than $L$ (PDF pages 44–48), and the correctness proof there relies on the fact that Dijkstra works correctly on the new graph. The deck does not present Dijkstra's steps or prove its correctness.

### Breadth-First Search for Unit Weights — PDF pages 13–17, 23–25 and 50–51
Breadth-first search (חיפוש לרוחב), written simply BFS in the slides, serves in this deck as a shortest-path tool whenever every edge can count as 1. The starting remark is that if all weights were 1, one could simply run BFS and it would work (PDF page 13). The deck uses it in three places. With integer weights from 1 to 10, each edge is first split into edges of weight 1 and BFS is run on the new graph, which gives linear time in total (PDF pages 14–17). On the unweighted tripartite graph of the matrix-multiplication reduction, BFS from every vertex is enough to serve as the APSP algorithm (PDF page 23). For the smallest weight limit $L$, BFS replaces the shortest-path computation and only checks whether the target is reached after the heavy edges are removed; repeating it inside a binary search over $L$ gives $O((E+V)\log W)$ (see PDF page 51; formula not fully extractable).

## Worked Examples
### Example: Lightest Paths That Use a Given Edge — PDF pages 2–8
Lightest paths that use a given edge (מסלולים קלים ביותר המשתמשים בקשת מסויימת) is the first exercise. Given a directed weighted graph $G=(V,E)$ and a special edge $(a,b) \in E$, describe an algorithm, with as good a complexity as you can, that finds for every pair of vertices $u, v \in V$ the lightest path $u \to v$ that uses the edge $(a,b)$; analyze its complexity and prove its correctness.

The solution starts from an observation: every path $u \to v$ that passes through $(a,b)$ has the form $u \to a \to b \to v$. The two parts do not depend on each other, so both $u \to a$ and $b \to v$ should be optimal. Run Bellman-Ford from $b$ to find the lightest path from $b$ to every other vertex; Bellman-Ford is used because the weights can be negative. To find the lightest path from every vertex to $a$, rather than running Floyd-Warshall and reading off the lightest paths to $a$, reverse the graph and run Bellman-Ford from $a$. Finally, for given $u, v$, one part of the path is the lightest path from $b$ to $v$, and the other is the lightest path from $a$ to $u$ in the reversed graph, which has to be reversed; the edge $(a,b)$ joins them. The time complexity is that of Bellman-Ford, $O(VE)$. A formal proof of the solution is left as homework (תרגיל לבית).

### Example: Lightest Path with Integer Weights 1 to 10 — PDF pages 9–17
The lightest path with weights 1…10 exercise (מסלול הכי קל עם משקלים 1...10) is told as a story: Michal wants to get from Rosh HaNikra (ראש הנקרה) to Eilat (אילת), passing through roads and cities, where the cost of each road is an integer between 1 and 10; help her plan the route. The slides draw a road graph whose extracted edge labels are 2, 5, 1, 1, 5, 5, 1, 8, 2, 6, 3, 2; the layout and whatever the repeated builds highlight are not recoverable (see PDF pages 10–12; diagram not fully extractable).

Clearly one can simply run Dijkstra's algorithm, but the goal is to improve the solution to linear time. If all weights were 1, plain BFS would work. Therefore every edge is split into edges of weight 1; for example, an edge of weight three becomes three edges of weight 1 (PDF pages 14–15). BFS on the new graph then gives the answer. The slides ask why the splitting is linear and answer that each edge is split into at most 10 edges, which is constant time per edge, so the whole algorithm runs in linear time.

### Example: Boolean Matrix Multiplication via APSP — PDF pages 18–25
Boolean matrix multiplication via APSP (כפל מטריצות בינאריות באמצעות APSP) asks how to use an assumed APSP algorithm for general weights, for example Floyd-Warshall, to multiply two binary matrices under the OR/AND product (PDF pages 19–20). The APSP algorithm is used as a black box.

Given binary matrices $A, B$, build the following tripartite graph (גרף תלת צדדי) with three sides $I$, $J$, $K$: the edge $(I_i, J_j)$ is in the graph if and only if $A_{ij} = 1$, and the edge $(J_i, K_j)$ is in the graph if and only if $B_{ij} = 1$. The figure draws the sides as three columns of vertices (see PDF page 22; diagram not fully extractable). Run APSP on this graph; since it has no weights, even BFS from every vertex works. Then assemble $C = AB$ by setting $C_{ij} = 1$ if and only if the shortest path between $I_i$ and $K_j$ has length exactly 2. Building the graph takes $O(n^2)$ time (the slide adds "$V = n$"), and so does assembling $C$ once the APSP results are available. The method therefore multiplies binary matrices in quadratic time plus the time of APSP; its correctness proof appears under Theorems and Proofs.

### Example: Lightest Path with a Half-Price Coupon — PDF pages 30–35
The lightest path with a coupon exercise (מסלול קל ביותר עם קופון) is told as a trip: on semester break you fly to New Zealand on many connecting flights, because as students you want to save, and you are given the airports, the flights between them and the price of each flight. Sharon the TA, who has become a flight attendant, lets you pay half the original price for one flight of your choice. Plan the route and the flight to halve so that you pay a minimal price. In other words, given a weighted graph with positive weights and two vertices $u, v$, find the edge whose weight to halve and the shortest path between the vertices.

If the halved edge is $(a,b)$, the price is $w(u \to v) = w(u \to a) + \frac{w(a,b)}{2} + w(b \to v)$. As in the first exercise, run Dijkstra's algorithm from $u$, and reverse the graph and run Dijkstra from $v$, to get the costs from $u$ to every $a$ and from every $b$ to $v$. Then go over all edges and take $e = \arg\min_{e=(a,b) \in E} \left( w(u \to a) + \frac{w(e)}{2} + w(b \to v) \right)$. The path is $u \to a$, the edge $e$, then $b \to v$, and $e$ is the edge to halve. Two Dijkstra runs cost $O(E + V\log V)$ and each edge then takes a constant amount of work, so the total is $O(E + V\log V)$.

### Example: Shortest Alternating-Color (Zigzag) Path — PDF pages 36–42
The shortest zigzag path exercise (מסלול מזגזג הכי קצר) gives a directed graph with edge weights, where each edge is either red or blue, and two marked vertices $s, t$. Find the lightest path from $s$ to $t$ whose colors zigzag: blue, red, blue, red and so on, or the opposite, red, blue, red and so on. Aim for $O(VE)$ time.

The graph is duplicated (נשכפל את הגרף): for every vertex $v$ add a vertex $v'$. A red edge $(u,v)$ becomes the edge $(u, v')$ and a blue edge $(u,v)$ becomes $(u', v)$, so red edges go from left to right, blue edges from right to left, and no edge stays inside a side. The figure shows a small example with vertices $a, b, c$ and copies $a', b', c'$ (see PDF page 38; diagram not fully extractable). Now every path in the new graph is a zigzag path and no zigzag path is lost; the slides leave "why?" to the student. A path starts either at $s$ or at $s'$, so Bellman-Ford is run from both and the shortest result is taken, with "where do we need to arrive?" also left open. That shortest path is the shortest zigzag path, and the running time is that of Bellman-Ford. A homework question (שאלה לבית) asks how the algorithm could be made more efficient.

### Example: Lightest Path with an Edge-Weight Limit — PDF pages 43–48
The lightest path with bounded edge weights exercise (מסלול הכי קל עם קשתות במשקל מוגבל) sends Sharon the TA from Metula (מטולה) to Eilat through a network of roads and cities, where every road has a nonnegative price. His budget is limited to $L$ shekels per road: he should reach the destination at minimum cost without using any road that costs more than $L$. The slides give the example $L = 7$ on a road graph whose extracted edge labels are 8, 5, 4, 1, 5, 5, 1, 8, 2, 6, 3, 2; the layout is not recoverable (see PDF pages 45–46; diagram not fully extractable).

Edges of weight greater than $L$ are useless, because they cannot be traversed at all, so delete them and run Dijkstra's algorithm on the new graph. If the destination cannot be reached, report that it is impossible; otherwise return the lightest path. The correctness proof is by contradiction (see Theorems and Proofs), and the time complexity is Dijkstra's, $O(E + V\log V)$.

### Example: Smallest Edge-Weight Limit by Binary Search — PDF pages 49–51
The smallest edge-weight limit problem is introduced on PDF page 49 as "a different problem" (בעיה אחרת) under the same heading (מסלול הכי קל עם קשתות במשקל מוגבל). Given a directed graph with edge weights in the range $1 \ldots W$ and two marked vertices $s, t$, find the minimum number $L$ for which there is a path $s \to t$ whose edges all weigh at most $L$; in standard terminology this is a minimum bottleneck path question, although the slides do not use that name. Aim for $O((E+V)\log W)$ (see PDF page 49; formula not fully extractable).

The solution is similar to the previous one, but instead of finding a shortest path it simply runs BFS, and the minimum $L$ is found by binary search (חיפוש בינארי). Choose $L = W/2$, remove the edges heavier than $L$ (the slide's wording is "the edges of weight $L$"), and run BFS. If the target is reached, choose $L = W/4$; otherwise $L = 3W/4$. Continue this way until reaching the minimum $L$ for which a path exists. The binary search takes at most $\log W$ steps, each running one BFS, so the total time complexity is $O((E+V)\log W)$.

## Theorems and Proofs
### Correctness of the Matrix-Multiplication Reduction — PDF pages 26–29
The correctness of Boolean matrix multiplication via APSP (כפל מטריצות בינאריות באמצעות APSP) rests on the claim that $C_{ij} = 1$ if and only if the shortest path between $I_i$ and $K_j$ has length exactly 2. First direction: suppose the path indeed has length two, that is, there is an $r$ for which $A_{ir} = B_{rj} = 1$; by the definition of the matrix product, $C_{ij} = 1$. Conversely, suppose $C_{ij} = 1$; by definition there is an $r$ such that $A_{ir} = B_{rj} = 1$, and the path is $I_i \to J_r \to K_j$. Hence the algorithm indeed solves the binary matrix multiplication problem in quadratic time plus the time of APSP.

The slides then ask what this means. Suppose you worked very hard and managed to improve APSP to time $o(n^3)$; the slides point out that the result works even if the weights are only $1$ and $\infty$. Then you would also have shown an improvement for binary matrix multiplication, without doing any further work at all.

### Correctness of Deleting Over-Limit Edges — PDF pages 47–48
The correctness proof (הוכחת הנכונות) for the edge-weight limit exercise is called relatively immediate in the slides. The algorithm deletes every edge of weight greater than $L$ and runs Dijkstra's algorithm on the new graph. Suppose, for contradiction (נניח בשלילה), that there was a lighter path that does not pass through any edge of weight greater than $L$. Then that path is contained in the new graph. Since Dijkstra's algorithm works correctly, it finds the lightest path in the new graph, which contradicts the assumption that there was a lighter path. The argument takes the correctness of Dijkstra's algorithm as given.
