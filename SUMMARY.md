# Project Summary — Course Tutor (Curriculum-Gated Hybrid RAG)

A local-first, free-to-run tutoring chatbot for an algorithms course, rebuilt from the
ground up. This document summarizes what changed, why, and what's now measured.

## What this project is

`app.py` is a Streamlit chat app where a student picks their current tutorial/week and
either asks free-form questions ("Learn" mode) or works through Socratic-style homework
help ("Homework" mode). Every answer is generated by an LLM (local via Ollama by default,
swappable to GitHub Models / OpenAI / any OpenAI-compatible server) grounded in retrieved
passages from the actual course material — never from the model's own knowledge — and is
physically prevented from citing material beyond the student's current week.

## The rethink (before → after)

| Before | After |
|---|---|
| One Chroma DB per tutorial, but retrieval was never actually queried at chat time — a static topic summary was pasted into the prompt instead | Every question performs real retrieval (dense/hybrid + optional reranking) against a single indexed collection |
| 8 separate per-tutorial vector stores | One Chroma collection; every chunk tagged with `tutorial: N` metadata |
| Curriculum boundaries enforced only by asking the LLM nicely in the prompt | Enforced at the **retrieval layer** via a `tutorial <= current_week` metadata filter — future material is physically unreachable, regardless of what the LLM would do (verified: 0/26 leaks in benchmark) |
| Naive fixed-size text chunks | Header-aware markdown chunking that preserves breadcrumbs (e.g. `Tutorial 4 › Worked Examples › Rod Cutting`) |
| No evaluation of embedding/LLM choices | A 30-question golden QA set + two benchmark scripts comparing embedding models and local LLMs, with results checked into the repo |
| No automated tests | 14 pytest tests covering the chunker, retrieval fusion (RRF), and integration paths |
| Generic default Streamlit look | A flat, neutral chat UI modeled on modern assistant UIs (ChatGPT/Claude/Gemini): hidden avatars, right-aligned user bubbles, plain full-width assistant text, a pill-style model/scope indicator, and suggestion chips |

## Benchmark results (see [BENCHMARK_RESULTS.md](BENCHMARK_RESULTS.md) and [BENCHMARK_LLM.md](BENCHMARK_LLM.md))

- **Embeddings:** `bge-small-en-v1.5` in dense mode wins — Hit@1 0.97, MRR 0.967, ~35 ms/query,
  beating `all-MiniLM-L6-v2` and tying `e5-small-v2` while indexing faster.
- **Curriculum gate:** 0/26 leaks when retrieval is restricted to one week before the
  answer's tutorial — the metadata filter, not the prompt, is what actually prevents
  spoilers.
- **Local LLMs (5 compared):** `llama3.2:3b` wins for a 4 GB VRAM laptop GPU — tied-best
  term coverage (0.92), the only 3B model with perfect 3/3 curriculum refusal, TTFT 1.6 s,
  81 tok/s. `phi4-mini` is the runner-up; `gemma3:4b` and `mistral:latest` refused nothing.
  The 0.00–1.00 refusal spread shows prompt-level curriculum enforcement is model-dependent
  and unreliable — which is exactly why the retrieval-level gate exists as the real safety
  mechanism rather than relying on prompt instructions.
- **Cheap cloud models:** attempted via GitHub Models (`openai/gpt-4o-mini` etc.) with a
  valid token, but the platform returned HTTP 410 `github_models_retirement_brownout` —
  GitHub is retiring the free Models API. The benchmark keeps `github:<model>` support for
  non-brownout windows; `LLM_PROVIDER=openai` remains the cheap-cloud path (~$0.15/M input
  tokens for gpt-4o-mini).

## Architecture

```
material/english/tutorial_*.txt
        │  build_index.py
        ▼
header-aware chunker → Chroma "course" collection (dense embeddings)
        │
        ▼  HybridRetriever.retrieve(query, max_tutorial=week, mode=...)
        │     - dense (cosine over bge-small-en-v1.5)
        │     - bm25 (rank_bm25 lexical channel)
        │     - hybrid (RRF fusion) + optional cross-encoder rerank
        ▼
tutor_system_prompt() / homework_system_prompt() → get_llm() (Ollama/GitHub/OpenAI/compatible)
        ▼
app.py — streamed answer + source citations, gated to tutorial <= current week
```

## Key files

- `rag_engine.py` — chunking, embeddings, hybrid retrieval, curriculum gate, LLM provider
  factory, prompt construction.
- `build_index.py` — CLI to (re)build the vector index from `material/`.
- `app.py` — the Streamlit chat UI.
- `benchmark_embeddings.py` / `benchmark_llm.py` — reproducible comparisons, results
  written to `BENCHMARK_RESULTS.md` / `BENCHMARK_LLM.md`.
- `eval/golden_qa.json` — 30-question golden retrieval set used by the embedding benchmark.
- `tests/test_rag.py` — pytest suite (`pytest` to run).
- `legacy/` — superseded scripts/docs from the original implementation, kept for reference.

## Running it

```powershell
./run.ps1                 # builds the index if missing, then launches Streamlit
# or manually:
python build_index.py
streamlit run app.py
```

Swap LLM providers by editing `LLM_PROVIDER` in `.env` (`ollama` | `github` | `openai` |
`compatible`) — no code changes required. See `.env.example` for all options.
