# Tutorial 1 — Algorithm Analysis & Asymptotic Notation

## Core Concepts

### Algorithm Definition
An **algorithm** is a systematic method for performing operations on a given input to produce an output. In this course, we will focus exclusively on **deterministic algorithms**, which yield the same output for a specific input every time.

### Key Components of an Algorithm
When discussing an algorithm, we will consider three main aspects:
1. **Description**: A step-by-step explanation of the algorithm.
2. **Complexity Claim**: An assertion regarding the algorithm's complexity.
3. **Correctness Claim**: An assertion regarding the algorithm's correctness.

### Types of Algorithms
- **Decision Algorithms**: These algorithms answer yes/no questions (e.g., Is there a path between two nodes in a graph?).
- **Optimization Algorithms**: These algorithms seek the best solution (e.g., What is the shortest path between two nodes?).

## Algorithms & Complexity

### Pseudocode Example
A common way to describe algorithms is through **pseudocode**, which resembles programming code but lacks strict syntax rules. Here’s an example of a pseudocode algorithm to check if \( y \) is divisible by \( x \):

```plaintext
function isDivisible(y, x):
    if x == 0:
        return false
    else:
        y = y % x
        if y == 0:
            return true
        else:
            return false
```

### Complexity Analysis
- **Time Complexity**: The time complexity of an algorithm is a measure of the amount of time it takes to run as a function of the length of the input.
- **Space Complexity**: The space complexity measures the amount of memory space required by the algorithm as a function of the input size.

### Asymptotic Notation
- **Big-O Notation (O)**: \( f(n) = O(g(n)) \) if there exist constants \( c \) and \( n_0 \) such that \( f(n) \leq c \cdot g(n) \) for all \( n \geq n_0 \).
- **Omega Notation (Ω)**: Represents a lower bound.
- **Theta Notation (Θ)**: Represents a tight bound (both O and Ω).

### Complexity Hierarchy
The following hierarchy illustrates the growth rates of common complexities:
- \( O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(2^n) < O(n!) \)

### Counting Operations
- For loops, the number of operations is multiplied by the number of iterations.
- For nested loops, the total number of operations is the product of the number of iterations at each level.

### Specific Algorithms
- **Insertion Sort**: 
  - Worst-case: \( O(n^2) \)
  - Best-case: \( O(n) \)
- **Selection Sort**: Always \( O(n^2) \)
- **Bubble Sort**: Always \( O(n^2) \)

### Formal Limit Definitions
- \( f = O(g) \) if and only if \( \limsup \frac{f(n)}{g(n)} < \infty \).

## Theorems & Proofs

### Theorem 1: Asymptotic Relationships
- \( f \in O(g) \) if \( \lim_{n \to \infty} \frac{f(n)}{g(n)} < \infty \)
- \( f \in \Omega(g) \) if \( 0 < \lim_{n \to \infty} \frac{f(n)}{g(n)} \)
- \( f \in \Theta(g) \) if \( 0 < \lim_{n \to \infty} \frac{f(n)}{g(n)} < \infty \)

### Theorem 2: Stronger Asymptotic Descriptions
- \( f \in o(g) \) if \( \lim_{n \to \infty} \frac{f(n)}{g(n)} = 0 \)
- \( f \in \omega(g) \) if \( \lim_{n \to \infty} \frac{f(n)}{g(n)} = \infty \)

## Worked Examples

### Example 1: Complexity Calculation
Given an algorithm with a time complexity of \( n^2 + 3n + 2 \):
- As \( n \) grows large, the \( n^2 \) term dominates.
- Thus, the complexity is \( O(n^2) \).

### Example 2: Comparing Algorithms
Consider two algorithms with complexities \( O(n) \) and \( O(n^2) \):
- For large \( n \), the \( O(n) \) algorithm will perform significantly better than the \( O(n^2) \) algorithm.

## Practice Problems (with solutions)

### Problem 1: Maximum Input Size
Given six algorithms with the following complexities:
1. \( n^2 \)
2. \( n^3 \)
3. \( 100n^2 \)
4. \( 2^n \)
5. \( 2^{2n} \)
6. \( n \log_2 n \)

Calculate the maximum input size \( n \) for which each algorithm completes in under one hour, assuming a computer can perform \( 10^{10} \) operations per second.

**Solution**:
- For \( n^2 \): Solve \( n^2 \leq 3.6 \times 10^{11} \) → \( n \approx 60000 \)
- For \( n^3 \): Solve \( n^3 \leq 3.6 \times 10^{11} \) → \( n \approx 7000 \)
- For \( 100n^2 \): Solve \( 100n^2 \leq 3.6 \times 10^{11} \) → \( n \approx 600 \)
- For \( 2^n \): Solve \( 2^n \leq 3.6 \times 10^{11} \) → \( n \approx 38 \)
- For \( 2^{2n} \): Solve \( 2^{2n} \leq 3.6 \times 10^{11} \) → \( n \approx 19 \)
- For \( n \log_2 n \): Solve \( n \log_2 n \leq 3.6 \times 10^{11} \) → \( n \approx 10^7 \)

### Problem 2: Order of Growth
Given the functions:
1. \( f_1(n) = 10n \)
2. \( f_2(n) = n^{1.3} \)
3. \( f_3(n) = n^n \)
4. \( f_4(n) = \log_2 n \)
5. \( f_5(n) = 2 \log_2 n \)

Order them such that each function \( f \) that appears after \( g \) satisfies \( g = O(f) \).

**Solution**:
1. \( f_4(n) = \log_2 n \)
2. \( f_5(n) = 2 \log_2 n \)
3. \( f_1(n) = 10n \)
4. \( f_2(n) = n^{1.3} \)
5. \( f_3(n) = n^n \)

## Common Mistakes to Avoid
- Confusing Big-O with Big-Ω: Remember that Big-O provides an upper bound, while Big-Ω provides a lower bound.
- Miscounting operations in nested loops: Always multiply the number of iterations at each level.
- Neglecting edge cases when analyzing algorithms: Always consider special cases that may affect performance or correctness.

By understanding these concepts and practicing the problems, students will be well-prepared for the complexities of algorithm analysis and design.
