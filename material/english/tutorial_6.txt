### Counting Equal-Sum Splits of {1, …, n} — PDF pages 1–2
Given $n$, the exercise asks how many different ways there are to split the set $\{1, \dots, n\}$ into two different sets whose union is $\{1, \dots, n\}$ and whose sums are equal. The required bounds are $O(n^3)$ time and $O(n^3)$ space, and the slides present it as a dynamic programming (DP) problem. Observation: if $1 + 2 + \dots + n$ is odd, there is no solution.

### The Dynamic Programming Table — PDF pages 3–5
The solution defines a two-dimensional array $A[n][\frac{n(n+1)}{4}]$; the second index runs up to half of the total sum $\frac{n(n+1)}{2}$, and $A[i][k]$ counts the subsets of $\{1, \dots, i\}$ whose sum is $k$. The array is filled from top to bottom and from left to right. Starting values: if $i = 1$ and $k \ge 2$ then $A[1][k] = 0$, and $A[i][1] = 1$ for every $i$. The recursive formula on PDF page 5 is: $A[i][k] = 0$ if $k > \frac{i(i+1)}{2}$; $A[i][k] = 1$ if $k = \frac{i(i+1)}{2}$; $A[i][k] = A[i-1][k] + A[i-1][k-i]$ if $i < k < \frac{i(i+1)}{2}$ (subsets without $i$ plus subsets with $i$); and $A[i][k] = A[i-1][k]$ if $0 < k \le i$, as written on the slide.

### Distance Function (d(u,v)) — PDF page 29
The distance function, denoted as $d(u,v)$, represents the shortest path length between nodes $u$ and $v$ in the graph. If $d(S,v) < \text{infinity}$, it means there is a path from node $S$ to node $v$.  If $d(S,v) < \text{infinity}$, then $dist[v] < \text{infinity}$.

### Proof by Contradiction — PDF page 29
To prove the correctness of the algorithm, we can use a proof by contradiction. Suppose there exists a node $v$ such that $d(S,v) < \text{infinity}$ but $dist[v] = \text{infinity}$.  Specifically, consider the shortest path from $S$ to this node $v$, which has a length of $k$.  The penultimate node on this path is closer to $v$ than $v$ itself, and therefore has been processed, but $dist[v]$ remains infinite.

### BFS Tree and Graph Properties — PDF pages 45–46
This lecture introduces the concept of a Breadth-First Search (BFS) tree. The BFS tree for an undirected, connected graph will contain all the edges used in the BFS traversal, with each level 𝑖 containing all the nodes at a distance 𝑖 from the source. ### Numbering DAGs — PDF page 64

## Methods and Procedures
### Graph Representations — PDF page 8
Graphs can be represented in several ways. A common representation is using an adjacency matrix A[n][n], where A[i][j] = 1 if there is an edge between nodes i and j, and 0 otherwise. This representation is useful for algorithms that operate on the graph's structure.

### Adjacency List Representation — PDF page 9
Another representation is using an adjacency list. This representation uses an array of lists, where each element of the array represents a node and contains a list of its adjacent nodes. This representation is more space-efficient for sparse graphs (graphs with relatively few edges).

### Breadth-First Search (BFS) — PDF page 12
BFS is a graph traversal algorithm that explores a graph level by level. It starts at a given source node and visits all its immediate neighbors before moving on to the next level of neighbors. This algorithm is used to find the shortest path between two nodes in an unweighted graph.

### Algorithm Correctness - Property 1 — PDF page 29
If $d(S,v) < \text{infinity}$, then $dist[v] < \text{infinity}$. This property ensures that if a path exists from the source $S$ to node $v$, then the distance value for $v$ will eventually be calculated and assigned a finite value.  This is a fundamental step in the algorithm's correctness.

### Algorithm Correctness - Property 2 — PDF page 30
Once a node $v$ is processed such that $d(S,v) = k$, all nodes $u$ with $d(S,u) \text{≤ } k$ have already been discovered.  This property ensures that the algorithm systematically explores the graph, eliminating nodes that have been reached.

### Proof by Contradiction - Node u — PDF page 31
Let $v'$ be the penultimate node in the shortest path from the source $S$ to node $u$.  The distance from $v'$ to the source $S$ is at least $k-1$, since the shortest path from $S$ to $v$ has length $k$.  Furthermore, the distance from $u$ to the source $S$ is exactly $d(S,u') = d(S,u) - 1$.  This establishes a relationship between the distances to $v'$ and $u$.

### Proof by Contradiction - Key Insight — PDF page 32
Assuming that $k' = d(S,u) \text{≤ } k$, we can observe that the claim holds for $u'$ and $v'$ because we have chosen $v$ and $u$ to be the first nodes in the path.  Therefore, by the inductive step, when processing node $v'$, node $u'$ should already have been discovered, leading to a contradiction.

### Algorithm Correctness - Property 3 — PDF page 33
When processing node $v$, all nodes $u$ with $d(S,u) \text{≤ } k$ have already been processed.  This property is crucial for ensuring that the algorithm terminates correctly.  The contradiction arises when the algorithm attempts to process a node that has already been processed.

### Data Structure for the Algorithm — PDF page 40
The algorithm uses a data structure to keep track of the nodes that have been processed. The nodes that have not been processed are referred to as 'unexplored' nodes. The nodes that have been processed but not yet assigned a distance value are referred to as 'live' nodes.

### Efficient DAG Numbering Algorithm — PDF pages 65–69
A naive algorithm to number a DAG would take O(V*E) time. To improve this, we can preprocess the graph by creating a list of nodes with an indegree of zero. This takes O(V+E) time. Then, we select one of these nodes arbitrarily and number it 1. We then decrement the indegree of all nodes connected to this node by one, and if any of these nodes now have an indegree of zero, we add them to the list of nodes with an indegree of zero. This process is repeated until all nodes have been numbered. This approach achieves a time complexity of O(V+E).

### Topological Sorting for Route Counting — PDF page 89
To count the number of flower routes, the graph must first be sorted topologically. If vertex $v$ is less than vertex $u$, the number of routes is zero because a DAG route must be monotonically increasing, and therefore it's impossible to reach $v$ from $u$. This sorting is a key step in the algorithm.

### Dynamic Programming Approach — PDF pages 90–91
The problem is solved using dynamic programming. For each node $w$, we store the number of ways to reach $w$ from $u$ in $ways(w)$.  The base case is $ways(u) = 1$, representing the trivial path. We then iterate through the topologically sorted graph, updating $ways(w)$ by summing the $ways(r)$ for all edges $(w, r)$.

### Iterating Through the Topological Sort — PDF pages 91–92
We iterate through the graph in the order determined by the topological sort, starting from $u$. For each node $w$, we update $ways(w)$ as the sum of $ways(r)$ for all edges $(w, r)$ in the graph. We stop when we reach vertex $v$.

### Proof by Induction — PDF pages 94–97
The algorithm's correctness is proven by induction on the topological index of each vertex. The base case is $ways(u) = 1$, as there is only one path: not to move.  Inductively, we assume $ways(j)$ is correct for all $j < i$, and we show that $ways(i)$ is also correct. The paths are monotonically increasing, so the only way to reach $i$ is from vertices smaller than $i$.

## Theorems and Proofs
### Result and Complexity — PDF page 6
The algorithm returns $A[n][\frac{n(n+1)}{4}] / 2$; each split is counted once from each of its two sets, hence the division by 2. The space complexity is $O(n^3)$. Each cell takes $O(1)$ time, which is possible because the table is scanned from top to bottom and from left to right; with $O(n^3)$ cells the total running time is $O(n^3)$.

### Algorithm Correctness - Proof of Distance Assignment — PDF page 41
After processing a node $v$ with $d(S,v) = k$, the distance to $v$ is assigned as $k$. This is because the shortest path to $v$ has length $k$, and all nodes on that path have already been processed and assigned distances less than or equal to $k$.  This completes the proof of the algorithm's correctness.

### Algorithm Termination - Proof by Induction — PDF page 41
The algorithm terminates because at any given time, the queue of nodes to be processed is divided into two parts: nodes with distance $k$ from the source and nodes with distance $k+1$ from the source (if any). This ensures that the algorithm progresses systematically.

### Complexity Analysis — PDF page 93
The topological sort takes linear time. After the sort, we iterate through the edges, and for each edge, we perform a constant number of operations. Therefore, the overall complexity of the algorithm is linear.

### Defining dist[v] as Shortest Cycle Length — PDF page 111
The lecture states that $dist[v]$ represents the length of the shortest cycle in $G$ from node $s$ to node $v$. This requires demonstrating three key points: (1) if $dist[v] = k < \text{infinity}$, then $k$ must be even, (2) a path of length $k$ exists from $s$ to $v$ in $G$, and (3) every path of length $\text{ℓ}$ from $s$ to $v$ has length less than or equal to $k$.

### Dist[v] = ∞ Case — PDF page 111
If $dist[v] = \text{infinity}$, then no cycle exists from $s$ to $v$ in the original graph $G$. This is a crucial condition for the shortest path algorithm.

## Graph Traversal — Reviewed Summary
### Breadth-First Search (BFS) — PDF pages 7–47
The supplied tutorial 6 slides also teach graphs and breadth-first search. BFS starts at a source with distance zero, places it in a FIFO queue, and discovers each previously unseen neighbor with distance one greater than the current vertex. Vertices are processed in nondecreasing distance from the source. Distances count edges in an unweighted graph. The discovery edges form a BFS tree; its levels are the shortest-path distances. For an undirected graph, an edge joins vertices on the same or adjacent BFS levels. With adjacency lists the traversal takes $O(|V|+|E|)$. Scanning every possible neighbor in an adjacency matrix can take $O(|V|^2)$.

### Multiple Sources and Search Trees — PDF pages 48–51; HW3_ALGO.pdf pages 1–2
To find unweighted distance from a set of sources, the tutorial adds a new source connected to every vertex in the set, runs BFS, and subtracts one from the computed distances. This construction preserves the intended edge-count metric.

### Directed Acyclic Graphs and Topological Ordering — PDF pages 55–70
A DAG is a directed graph with no directed cycle. A topological ordering puts the tail of every edge before its head. The slides give an indegree-based algorithm: initialize a queue of zero-indegree vertices, remove one, output it, and decrease the indegrees of its outgoing neighbors. Enqueue newly zero-indegree vertices. With adjacency lists, each vertex and edge is processed once, taking $O(|V|+|E|)$. If vertices remain when the queue empties, no topological ordering exists for the whole graph.

### Counting Paths in a DAG — PDF pages 87–95
After topologically sorting a DAG, initialize $ways(u)=1$ at the chosen start and zero elsewhere. Process vertices in topological order and add $ways(v)$ to the count of each outgoing neighbor. An edge only leads to a later vertex, so all contributions to a vertex are available before it is processed. The tutorial uses this combination of graph order and dynamic programming to count directed paths.

### Even-Length Paths and Layered Graphs — PDF pages 96–112
To enforce an even number of edges in an unweighted walk, duplicate each vertex into parity states. Every original edge switches parity. Run BFS from the even state of the source to the even state of a target. Returning to the even layer means an even edge count; BFS finds the smallest such count. Prove correspondence in both directions between original walks and paths in the state graph. A repeated original vertex can occur with different states, so do not silently claim that the projected walk must be simple.
