# Project Summary — Course Tutor (Curriculum-Gated Hybrid RAG)

## RAG update — September 2026

- Runtime curriculum rules now come from `db/curriculum.json`, shared by the UI,
  prompts, scope checks and homework concept IDs. `db/metadata.json` is a compatibility export.
- Dense hits carry measured cosine similarity. Relevance filtering and source-ID
  validation withhold weak evidence or nonexistent citations; neither proves entailment.
- Explicit method exclusions (including Hebrew) avoid treating "without Dijkstra"
  as a request to teach it. Original questions are retained, and ambiguous references
  ask for clarification. A subsequent term-normalization update is described below.
- Homework retrieval uses per-problem concept IDs and only the requested statements,
  instead of adding all assignment topics. Invalid problem numbers ask for clarification.
- `evaluate_rag.py` and `eval/rag_cases.json` evaluate specific supporting passages,
  unsupported questions, homework, future material, exclusions and reference-translated
  Hebrew cases. See `RAG_EVALUATION.md` for results and remaining misses; this is an
  offline regression evaluation, not a live model-quality guarantee.
- Corrected the missing strict-weight condition in the MST cycle property and the
  Prim example's last edge (total weight 6, not 8). The course index was rebuilt.
- No new reranking stage or translation-provider change was introduced.

## Homework assistance — September 2026

- Assignment statements now count as evidence independently of lecture matches.
  Contents/statement requests display the real PDF text; guidance can use both the
  selected statement and in-scope lecture passages. Weak retrieval retries with
  the problem's mapped prerequisite concepts.
- Natural problem references and explicit-problem follow-ups are supported; the
  active problem resets when the assignment changes. Standalone prerequisite questions
  use the regular teaching prompt, including Dijkstra on Homework 5. Tutoring instructions permit
  direct task explanations and stepwise solving, with one validated citation retry.
- The runtime syllabus is cumulative through the assignment week. The legacy
  curriculum extractor had a separate stale topic table, incorrect project root,
  and truncated PDFs. It now uses `db/curriculum.json`, all source pages, and a
  review directory. No course weeks were guessed or reassigned, and existing
  lecture notes were not automatically regenerated.

## Term normalization — September 2026

- `query_normalization.py` proposes close spelling matches from the curriculum and
  known abbreviation expansions; the selected tutor LLM approves only candidate IDs.
- The app applies approved edits before retrieval, scope checking and evidence
  filtering. Original wording remains visible and accompanies the interpretation
  in generation/history. Exclusions, numbers and formatted code/math stay intact.
- Short ambiguous abbreviations require recognizable course context. Invalid model
  output or a failed call preserves the original; clean queries avoid the extra call.
- The offline RAG evaluation does not invoke normalization. Separate tests cover
  edits, failures, scope restrictions, protected content and the chat integration.

A local-first, free-to-run tutoring chatbot for an algorithms course, rebuilt from the
ground up. This document summarizes what changed, why, and what's now measured.

## What this project is

`app.py` is a Streamlit chat app where a student picks their current tutorial/week and
either asks free-form questions ("Learn" mode) or works through Socratic-style homework
help ("Homework" mode). Every answer is generated by an LLM (local via Ollama by default,
swappable to GitHub Models / OpenAI / any OpenAI-compatible server) grounded in retrieved
passages from the actual course material — never from the model's own knowledge — and is
physically prevented from citing material beyond the student's current week.

## The rethink (before → after)

| Before | After |
|---|---|
| One Chroma DB per tutorial, but retrieval was never actually queried at chat time — a static topic summary was pasted into the prompt instead | Every question performs real retrieval (dense/hybrid + optional reranking) against a single indexed collection |
| 8 separate per-tutorial vector stores | One Chroma collection; every chunk tagged with `tutorial: N` metadata |
| Curriculum boundaries enforced only by asking the LLM nicely in the prompt | Enforced at the **retrieval layer** via a `tutorial <= current_week` metadata filter — future material is physically unreachable, regardless of what the LLM would do (verified: 0/26 leaks in benchmark) |
| Naive fixed-size text chunks | Header-aware markdown chunking that preserves breadcrumbs (e.g. `Tutorial 4 › Worked Examples › Rod Cutting`) |
| No evaluation of embedding/LLM choices | A 30-question golden QA set + two benchmark scripts comparing embedding models and local LLMs, with results checked into the repo |
| No automated tests | 14 pytest tests covering the chunker, retrieval fusion (RRF), and integration paths |
| Generic default Streamlit look | A flat, neutral chat UI modeled on modern assistant UIs (ChatGPT/Claude/Gemini): hidden avatars, right-aligned user bubbles, plain full-width assistant text, a pill-style model/scope indicator, and suggestion chips |

## Benchmark results (see [BENCHMARK_RESULTS.md](BENCHMARK_RESULTS.md) and [BENCHMARK_LLM.md](BENCHMARK_LLM.md))

- **Embeddings:** `bge-small-en-v1.5` in dense mode wins — Hit@1 0.97, MRR 0.967, ~35 ms/query,
  beating `all-MiniLM-L6-v2` and tying `e5-small-v2` while indexing faster.
- **Curriculum gate:** 0/26 leaks when retrieval is restricted to one week before the
  answer's tutorial — the metadata filter, not the prompt, is what actually prevents
  spoilers. A second **pre-LLM scope check** (`check_scope()`) probes the question against
  the full index: if it matches future material better than in-scope material, the app
  refuses deterministically before the LLM runs — 7/7 leak probes caught, 0/30 false
  refusals on the golden set. This closes the "LLM answers from its own knowledge" hole
  that prompt instructions alone cannot (small models refused 0–3 of 3 in the benchmark).
- **Local LLMs (5 compared):** `llama3.2:3b` wins for a 4 GB VRAM laptop GPU — tied-best
  term coverage (0.92), the only 3B model with perfect 3/3 curriculum refusal, TTFT 1.6 s,
  81 tok/s. `phi4-mini` is the runner-up; `gemma3:4b` and `mistral:latest` refused nothing.
  The 0.00–1.00 refusal spread shows prompt-level curriculum enforcement is model-dependent
  and unreliable — which is exactly why the retrieval-level gate exists as the real safety
  mechanism rather than relying on prompt instructions.
- **Cheap cloud models:** attempted via GitHub Models (`openai/gpt-4o-mini` etc.) with a
  valid token, but the platform returned HTTP 410 `github_models_retirement_brownout` —
  GitHub is retiring the free Models API. The benchmark keeps `github:<model>` support for
  non-brownout windows; `LLM_PROVIDER=openai` remains the cheap-cloud path (~$0.15/M input
  tokens for gpt-4o-mini).

## Architecture

```
material/english/tutorial_*.txt
        │  build_index.py
        ▼
header-aware chunker → Chroma "course" collection (dense embeddings)
        │
        ▼  HybridRetriever.retrieve(query, max_tutorial=week, mode=...)
        │     - dense (cosine over bge-small-en-v1.5)
        │     - bm25 (rank_bm25 lexical channel)
        │     - hybrid (RRF fusion) + optional cross-encoder rerank
        ▼
tutor_system_prompt() / homework_system_prompt() → get_llm() (Ollama/GitHub/OpenAI/compatible)
        ▼
app.py — streamed answer + source citations, gated to tutorial <= current week
```

## Key files

- `rag_engine.py` — chunking, embeddings, hybrid retrieval, curriculum gate, LLM provider
  factory, prompt construction.
- `build_index.py` — CLI to (re)build the vector index from `material/`.
- `app.py` — the Streamlit chat UI.
- `benchmark_embeddings.py` / `benchmark_llm.py` — reproducible comparisons, results
  written to `BENCHMARK_RESULTS.md` / `BENCHMARK_LLM.md`.
- `eval/golden_qa.json` — 30-question golden retrieval set used by the embedding benchmark.
- `tests/test_rag.py` — pytest suite (`pytest` to run).
- `legacy/` — superseded scripts/docs from the original implementation, kept for reference.

## Running it

```powershell
./run.ps1                 # builds the index if missing, then launches Streamlit
# or manually:
python build_index.py
streamlit run app.py
```

Swap LLM providers by editing `LLM_PROVIDER` in `.env` (`ollama` | `github` | `openai` |
`compatible`) — no code changes required. See `.env.example` for all options.

## Independent Hebrew translator — September 2026

- Sidebar and environment settings select auto, dedicated local Ollama, tutor, or
  OpenAI translation independently of the answering model. Hebrew input is
  translated to English; the checked English answer is translated back and only
  Hebrew is displayed. Code/math protection and citation checks remain active.
- Explicit local translation does not silently use a paid model on failure.
  DictaLM 3.0 1.7B Instruct is a candidate to evaluate, not an installed or
  quality-benchmarked default. `dictalm-translator` is an example Ollama alias.

## English answer refusal fix — September 2026

- Reproduced false insufficient-evidence decisions for beginner phrasing, “teach me”
  and short Big-O questions. Evidence keywords now omit presentation instructions;
  recognized topics can retry with canonical names while retaining original query
  constraints and curriculum filters.
- English input skips translator initialization. Learning mode now retries missing
  citations once, as homework mode does; invalid citation IDs remain rejected.
- Exact “what is dijkstra” at week 9 is included in real-index regressions.
