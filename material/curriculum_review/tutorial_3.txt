# Tutorial 3 — Greedy Algorithms

## Source and Scope
These English notes summarize the supplied Hebrew slides `material/lectures/Tutorial 3 (2).pdf` (74 PDF pages) from the course "Design and Analysis of Algorithms" (תכנון וניתוח אלגוריתמים). The deck is titled "אלגוריתמים חמדניים" ("Greedy Algorithms"), with the subtitle "תכנון וניתוח אלגוריתמים — תרגול שלישי" ("Design and Analysis of Algorithms — Third Tutorial"). Page references below refer to PDF pages (1–74); repeated animation slides are consolidated. The tutorial covers optimization problems and what makes an algorithm greedy; the two techniques the slides use to prove greedy optimality (the comparison argument and the exchange argument); coin change as an example where the obvious greedy rule fails; interval partitioning (seating all diners with the fewest tables); interval scheduling at a single table; a greedy $\ln|U|$ approximation for set cover; minimum vertex cover on trees; and the carpenter's beam-cutting problem with its equivalent hiking version. The slides do not cover knapsack problems or Huffman coding, and dynamic programming is mentioned only as the technique the fourth tutorial uses to solve coin change.

## Core Concepts
### Greedy Algorithms and Optimization Problems — PDF pages 2–3
A greedy algorithm (אלגוריתם חמדן) is introduced in the setting of optimization problems (בעיות אופטימיזציה). Most problems in the course are optimization problems: the goal is to find an optimal solution $opt$ out of a collection $X$ of feasible solutions. It is sometimes hard to say precisely whether an algorithm is greedy or not. In general, an algorithm is called greedy if at every step, among several possible options, it picks the best option according to some short-sighted criterion, without examining or taking into account the long term. Greedy algorithms are usually easy to find for various optimization problems, but only in certain cases are they ideal. In those cases you must prove that the greedy solution is the correct (optimal) one. The rest of the deck shows greedy algorithms argued to be optimal (interval partitioning, interval scheduling, vertex cover on trees, the carpenter problem), a problem where the obvious greedy rule fails (coin change), and an NP-hard problem where a greedy algorithm serves as an approximation (set cover).

### Comparison Argument (Greedy Stays Ahead) — PDF pages 4–5
The comparison argument (טיעון ההשוואה) is the first of the two main approaches the slides give for proving that a greedy algorithm is correct; English texts usually call this style "greedy stays ahead". Compare the greedy algorithm with any other algorithm at every step of the run, and show that at every step the greedy algorithm chooses a solution no worse than the other algorithm's. This shows that at every step the greedy algorithm is no worse than any other algorithm, so the final result is optimal as well, i.e. the greedy algorithm is optimal as required. In the deck the label is attached explicitly to the argument that the restaurant simulation uses a minimum number of tables (PDF page 23), and it is offered as one way to prove that the greedy tree vertex cover is minimal (PDF page 67). The proofs for single-table interval scheduling (PDF pages 29–30) and for the carpenter problem (PDF page 74) also compare the greedy solution with an optimal one position by position.

### Exchange Argument — PDF pages 6–7
The exchange argument (טיעון ההחלפה) is the second main approach. Start from some optimal solution and perform exchanges on it that do not harm its optimality, until reaching an equivalent solution that the greedy algorithm proposes. This shows that although the optimal solution we started from is not the solution the greedy algorithm outputs, it is equivalent to it. That is, the greedy algorithm does produce an optimal solution, since its solution is equivalent to any other optimal solution. In the deck, the exchange argument proves the key observation for minimum vertex cover on trees: replacing every leaf in a cover by its parent never makes the cover larger, so some minimum cover contains no leaf (PDF pages 49–51). It is also suggested as one of two ways to prove that the greedy tree cover is minimal, by comparing the greedy cover $A$ with an optimal cover $OPT$ (PDF pages 66–67).

### Depth and Maximum Depth of Intervals — PDF page 21
Depth (עומק) and maximum depth (העומק המקסימלי) give the lower bound in the restaurant problem, where each diner $i$ is an interval $p_i=(a_i,b_i)$ of arrival and departure times. If some moment is contained in $k$ different intervals, every solution uses at least $k$ tables; the depth of that moment is $k$. The maximum of the depths over all moments is the maximum depth, and it is therefore a lower bound on the number of tables in every solution. This sets the goal for the algorithm: build a greedy algorithm whose number of tables equals the maximum depth, and it will then be optimal. The correctness argument of the restaurant simulation (PDF pages 22–23) uses the same idea: a new table is opened only at a moment when all existing tables are occupied.

### Vertex Cover — PDF pages 45–48
A vertex cover (כיסוי בצמתים) of an undirected graph $G=(V,E)$ is a set of vertices $\tilde V\subseteq V$ such that for every edge $(v,u)\in E$, either $v\in\tilde V$ or $u\in\tilde V$ (or both). A minimum vertex cover (כיסוי מינימלי בצמתים) of $G$ is a minimum set of vertices that is a cover of $G$. On a general graph this is an NP-complete problem, i.e. a hard one; the slides note that it is studied extensively in the Computational Models course (מודלים חישוביים). The tutorial's exercise, "Minimum Vertex Cover on Trees" (כיסוי מינימלי בצמתים על עצים), asks for an algorithm on trees only, where a greedy algorithm based on leaves finds a minimum cover. The three definition slides repeat with identical extracted text, presumably animating a drawing (see PDF pages 46–48; diagram not fully extractable).

### Set Cover Problem — PDF pages 31–34
The set cover problem (בעיית הכיסוי בקבוצות) is: given a universe $U$ and a sequence of sets $S_1,S_2,\dots,S_m$, find a minimum number of sets $S_i$ whose union is the whole universe. In the slides' example, $U=\{1,2,3,4,5,6\}$ with $S_1=\{1,4,6\}$, $S_2=\{2,3,6\}$, $S_3=\{4,5\}$, $S_4=\{1,3,5\}$ and $S_5=\{1\}$; the minimum number of sets is 3, for example $S_1\cup S_2\cup S_3=U$. Unfortunately, set cover is NP-hard, so instead of an exact algorithm the slides look for a greedy approximation (קירוב חמדני); the section is titled "Set Cover Approximation" (קירוב לכיסוי בקבוצות). The quality of the approximation is measured against the size $c$ of an optimal cover (PDF pages 36–44).

## Algorithms and Complexity
### Interval Partitioning by Restaurant Simulation — PDF pages 22–23
Interval partitioning, the diner-seating problem (בעיית שיבוץ הסועדים, "The 'Scheduling all Intervals' Problem"), is solved by a greedy "simulation" of the restaurant. As in the diners problem of the first tutorial, sort all the interesting points (arrival and departure times) and go through them in order. Keep a list of free tables: it starts empty, and whenever a diner leaves, the table where that diner sat is added to it. Whenever a new diner arrives, seat the diner at one of the free tables that were already "opened"; if no table is free, a new table must be added and the diner is seated there. The slides say it is easy to see that the answer is optimal. If the algorithm used $x$ tables, there was at least one moment when the restaurant had $x-1$ tables and all of them were occupied, because that is the only condition for opening a new table. Hence it is impossible to seat the diners at fewer than $x$ tables, as required — a comparison argument. The running time is linear plus the cost of sorting.

### Earliest-Finish-Time Interval Scheduling — PDF pages 27–28
Interval scheduling at a single table (שיבוץ הסועדים בשולחן בודד, "The Interval Scheduling Problem") asks for a maximum number of pairwise disjoint intervals. The slides first raise two other rules: always choosing the interval that starts first, or choosing the shortest intervals first. The extracted text poses these only as questions, without counterexamples (see PDF page 27; diagram not fully extractable). The adopted greedy rule is: at every step, choose the interval that ends first. This way the table is freed as soon as possible, and at the same time a diner is served. When an interval is chosen for the solution, delete all intervals that intersect it, and repeat until the set of intervals is empty. If the set of points is given sorted, all of these operations can be performed in linear time; the slides leave the "how?" to the students. Correctness is proved by comparing the greedy solution with an optimal solution interval by interval (see Interval Scheduling: Correctness Proof below).

### Greedy Set Cover Approximation — PDF pages 35–37
The greedy set cover approximation (קירוב חמדני) works as follows: in the first step take the largest set; afterwards, at every step take the set that covers the most elements of the universe that are not yet covered; continue until everything is covered. The slides note that this clearly reaches a cover whenever one exists. The claim to be proved: if an optimal cover has size $c$, i.e. it contains $c$ sets, then the greedy cover has size $r\le c\cdot\ln|U|$. To avoid messy calculations, the slides actually prove $r-1\le c\cdot\ln|U|$ and write $k=r-1$ for convenience. As an exercise, students should convince themselves that a naive implementation takes at most $O(m^2|U|)$ time (see PDF page 37; formula not fully extractable). The proof is given below in two parts: coverage per stage, and the logarithmic bound.

### Leaf-Based Greedy for Vertex Cover on Trees — PDF pages 49–65
The greedy algorithm for minimum vertex cover on trees (כיסוי מינימלי בצמתים על עצים) rests on an observation proved with the exchange argument: there is a minimum vertex cover of a tree in which no leaf is in the cover. Replace every leaf in the cover by its parent; in the worst case the number of vertices in the cover stays the same, and if one of the parents was already in the cover, the new cover even becomes smaller. The algorithm: scan all vertices of the graph in linear time, store the degree of every vertex, and maintain a list of all leaves (vertices of degree 1) in the forest. While the leaf list is not empty, take a vertex $v$ out of the list, add its unique neighbor $u$ to the cover, and delete $v$, $u$ and all edges leaving $u$. PDF pages 52–65 repeat the same text, presumably animating the run on an example tree (see PDF pages 52–65; diagram not fully extractable). Validity and minimality are argued on PDF pages 66–67. The extracted text states that the initial scan takes linear time but gives no separate statement of the total running time.

### Farthest-Reachable Greedy for the Carpenter Problem — PDF page 73
The farthest-reachable greedy for the carpenter problem (בעיית הנגר) goes over the marked positions in order and, at every step, cuts the beam at the farthest marked position that is not farther than $L$ (that is, at most $L$ beyond the previous cut). Equivalently, in the hiking version, each day you walk to the farthest stopping station you can reach. The slides then raise the natural doubt: is this really the optimal solution? Perhaps on some days it is worth stopping before the farthest station so that the next day you can get farther? The proof on PDF page 74 answers this: the $r$-th greedy cut never comes before the $r$-th cut of an optimal solution (in fact, of any legal solution), so no legal solution uses fewer cuts. The extracted text gives no explicit running-time statement for this solution.

## Worked Examples
### Example: Coin Change and the Largest-Coin Greedy — PDF pages 8–17
The coin change problem (בעיית המטבעות) is posed as follows: given a set of $k$ distinct integer coin values $S=\{c_1,c_2,\dots,c_k\}$ and a target sum $n$, form the sum $n$ from coins of $S$. What is the minimum number of coins needed, which coins represent the sum minimally, and can $n$ be represented with these coins at all? Formally, $S\subset\mathbb{N}$, and we want $\sum_i\alpha_i$ to be minimal, where $\alpha_i\in\mathbb{N}$ and $n=\sum_{i=1}^{k}\alpha_i\cdot c_i$. A possible greedy solution: each time take the largest coin whose addition does not exceed the sum; the slides ask whether it works and how we would know that $n$ cannot be formed. For $S=\{1,3,4\}$ and $n=6$, greedy takes 4 (2 left), then 1 (1 left), then 1 (0 left), using 3 coins. But there is a better solution with only 2 coins, $3+3$. Conclusion: the trivial greedy solution does not work for coin change, and a single example where greedy fails is enough to refute its optimality. The fourth tutorial gives a correct and optimal solution using a technique called dynamic programming (תכנון דינאמי).

### Example: Seating All Diners with the Fewest Tables — PDF pages 18–23
Interval partitioning (בעיית שיבוץ הסועדים, "The 'Scheduling all Intervals' Problem") is posed as follows. You own a restaurant and have a list of $n$ distinct pairs $p_i=(a_i,b_i)$, the arrival and departure times of the diners. Describe an algorithm, with the best complexity you can, that assigns every diner $i$ to a suitable table while using a minimum number of tables, and prove its correctness and complexity. The example input on the slides is $p_1=(0,4)$, $p_2=(2,5)$, $p_3=(1,7)$, $p_4=(4,6)$, $p_5=(8,9)$. Solution approach as presented: first observe that a moment lying in $k$ intervals forces at least $k$ tables, so the maximum depth is a lower bound and an algorithm that uses exactly that many tables is optimal. Then simulate the restaurant: sort the interesting points, process them in order, seat each arriving diner at an already opened free table, return a table to the free list when its diner leaves, and open a new table only when no table is free. Optimality follows by the comparison argument, and the running time is linear plus sorting.

### Example: Seating Diners at a Single Table — PDF pages 24–30
Interval scheduling (שיבוץ הסועדים בשולחן בודד, "The Interval Scheduling Problem") is posed with the same list of $n$ distinct pairs $p_i=(a_i,b_i)$ of arrival and departure times. Now there is a single table, and you must choose which diners to seat and which to turn away (peacefully). Two diners cannot sit at the table at the same time, so the intervals of the chosen diners must be disjoint. Describe an algorithm, with the best complexity you can, that chooses which diners to seat so that their number is maximal, and prove its correctness and complexity. The same five example intervals are used: $(0,4)$, $(2,5)$, $(1,7)$, $(4,6)$, $(8,9)$. Solution approach as presented: after asking whether taking the earliest-starting or the shortest intervals would work, the slides repeatedly choose the interval that ends first and delete all intervals intersecting it, until none remain; this takes linear time if the points are given sorted. The proof shows by induction that the $r$-th greedy interval ends no later than the $r$-th optimal interval, and then that an optimal solution with more intervals would leave the greedy algorithm an interval it could still take.

### Example: Minimum Vertex Cover on a Tree — PDF pages 45–67
Minimum vertex cover on trees (בעיית כיסוי מינימלי בצמתים על עצים, "Minimum Vertex Cover on Trees") is posed as follows: describe an algorithm, with the best complexity you can, that given a tree finds a minimum vertex cover in it, and prove its correctness and complexity. The slides recall that on a general graph the problem is NP-complete. Solution approach as presented: first, by the exchange argument, some minimum cover contains no leaf, since every leaf in a cover can be replaced by its parent. Then compute all degrees and the list of leaves in a linear scan, and repeatedly take a leaf $v$, add its unique neighbor $u$ to the cover, and delete $v$, $u$ and all edges leaving $u$. The cover is legal because a leaf exists while edges remain and edges are deleted only after they are covered. Minimality can be shown by an exchange argument or by a comparison argument (for a leaf $v$ attached to $u$, it always pays off more to choose $u$); the slides leave completing both proofs as homework. The run on an example tree is shown only graphically (see PDF pages 52–65; diagram not fully extractable).

### Example: The Carpenter Problem and the Hiking Trip — PDF pages 68–74
The carpenter problem (בעיית הנגר) is posed as follows. A carpenter receives a wooden beam of total length $S$ to cut, with $n$ marked possible cut positions $x_1,x_2,\dots,x_n$; the carpenter may cut the beam only there. The client needs beams of length at most $L$: after cutting, every piece must be no longer than $L$. Describe an algorithm, with the best complexity you can, that chooses the cut positions so that the number of pieces of length at most $L$ is minimal, and prove its correctness and complexity. The slides then retell it as "another story, the same problem" (סיפור אחר, אותה הבעיה): a route of length $S$ has $n$ distinct stopping points $x_1,\dots,x_n$, you can walk at most $L$ per day, and you must choose overnight stops among these points so as to finish the route in a minimum number of days. Solution approach as presented: go over the marked positions in order and always cut at the farthest marked position not farther than $L$ (equivalently, walk each day to the farthest reachable stop); optimality is proved by contradiction, using the fact that the $r$-th greedy cut never comes before the $r$-th cut of an optimal solution.

## Theorems and Proofs
### Interval Scheduling: Correctness Proof — PDF pages 29–30
The correctness proof (הוכחת נכונות) for earliest-finish-time interval scheduling denotes the greedy solution by $A=\{p_{i_1},p_{i_2},\dots,p_{i_k}\}$ and the intervals of another optimal solution by $OPT=\{p_{j_1},p_{j_2},\dots,p_{j_m}\}$, where $a$ denotes a start time and $b$ an end time. Auxiliary claim (טענת עזר), by induction: for every $r\le k$, $b_{i_r}\le b_{j_r}$; the first greedy interval ends no later than the first optimal interval, and likewise the second, the third, and so on. Base, $r=1$: the greedy algorithm picks the interval that ends first, so $b_{i_1}\le b_j$ for every $j$. Step: assume $b_{i_{r-1}}\le b_{j_{r-1}}$ and suppose, for contradiction, that $b_{i_r}>b_{j_r}$; students are asked to convince themselves that this is a contradiction, because the greedy algorithm would have chosen $p_{j_r}$ instead of $p_{i_r}$. Main argument: $|A|=k$ and $|OPT|=m$, and we want $m=k$. Suppose, for contradiction, that $m>k$, and look at the extra interval of $OPT$. By the claim $b_{i_k}\le b_{j_k}$, and $b_{j_k}\le a_{j_{k+1}}$ because the $(k+1)$-th optimal interval starts after the $k$-th ends. Hence $b_{i_k}\le a_{j_{k+1}}$, so the greedy algorithm could still take $p_{j_{k+1}}$; yet it stopped, a contradiction.

### Set Cover: Coverage per Stage — PDF pages 38–40
The set cover analysis (בעיית הכיסוי בקבוצות) tracks the number of uncovered elements. Suppose that at stage $i$ of the greedy algorithm $x_i$ elements remain uncovered; of course $x_0=|U|$. Claim: at stage $i$ at least $x_i/c$ elements are covered. We know that there are $c$ sets that can cover the remaining elements, so by the pigeonhole principle (שובך היונים) at least one set contains at least $x_i/c$ of them. Since a set with that many elements exists, in particular the maximal set chosen by the greedy algorithm contains at least $x_i/c$ of them. Therefore $x_{i+1}\le x_i-\frac{x_i}{c}=x_i\left(1-\frac{1}{c}\right)$: every stage covers at least a $1/c$ fraction of the elements that are still uncovered, where $c$ is the size of an optimal cover.

### Set Cover: Deriving the Logarithmic Bound — PDF pages 41–44
The logarithmic approximation bound for greedy set cover (קירוב לכיסוי בקבוצות) follows from the per-stage inequality. Let iteration $k$ be the one before the last (the slides ask why). Then $x_k\le x_0\left(1-\frac{1}{c}\right)^k=|U|\left(1-\frac{1}{c}\right)^k$. On the other hand, since $k$ is the iteration before the last, at least one element was still left to cover, so $1\le x_k\le|U|\left(1-\frac{1}{c}\right)^k=|U|\left(\left(1-\frac{1}{c}\right)^c\right)^{k/c}$. Using the fact that $\left(1-\frac{1}{a}\right)^a\le\frac{1}{e}$ gives $1\le|U|\left(\frac{1}{e}\right)^{k/c}$, hence $e^{k/c}\le|U|$ and $k\le c\cdot\ln|U|$. Since $r=k+1$, this shows, up to $\pm1$ as the slides put it, that $r\le c\cdot\ln|U|$. Thus the greedy algorithm achieves a $\ln|U|$ approximation of the optimum: it uses at most about $\ln|U|$ times as many sets as an optimal cover.

### Tree Vertex Cover: Validity and Minimality — PDF pages 66–67
The correctness proof (הוכחת נכונות) for the leaf-based tree vertex cover algorithm first shows that the cover it returns is legal. As long as the graph has edges, a leaf exists, so the algorithm ends only when no edges remain. Edges are removed from the graph only after they are covered, so every edge is covered as required. Minimality can be proved in two ways, which the slides only outline. By an exchange argument: compare the greedy cover $A$ with another optimal cover $OPT$; the slides leave open how the two covers can be compared. By a comparison argument: look at some leaf $v$ and the vertex $u$ it is attached to. At least one of them must be in the cover; consider what happens if $v$ is chosen, and prove that it always pays off more to choose $u$. Completing both correctness proofs is left as homework (תרגיל לבית).

### Carpenter Problem: Correctness Proof — PDF page 74
The correctness proof (הוכחת נכונות) for the carpenter greedy denotes the greedy solution by $A=\{x_{i_1},x_{i_2},\dots,x_{i_k}\}$, with $k$ cuts, and assumes an optimal solution $OPT=\{x_{j_1},x_{j_2},\dots,x_{j_m}\}$ that is better, i.e. $m<k$. As in the single-table scheduling argument, $x_{i_r}\ge x_{j_r}$ for every $r\le m$: the $r$-th cut of the greedy solution does not come before the $r$-th cut of the optimal solution (and in fact of any legal solution). Proving this by induction on $r$ is left as a good homework exercise. In particular $x_{i_m}\ge x_{j_m}$, so the last cut of the optimal solution does not come after the $m$-th greedy cut. Since the $m$-th cut is not the last cut of the greedy solution, at least $L$ more units follow it, which the slides write as $x_{i_m}<S-L$. Altogether $x_{j_m}<S-L$. But this is the last cut of the optimal solution, so it must be at distance at most $L$ from the end point $S$; hence this cut is not legal, a contradiction.
